# 安全控制与审计接口

接口为同步本地 32 位寄存器口，地址按字节计且 4 字节对齐。`cfg_write`、地址、数据在上升沿采样，下一拍观察 `cfg_error`；提交期间 `cfg_ready=0`，禁止写入。读数据为组合输出，地址稳定后采样。它不是 AXI/Avalon、以太网远程管理口或原核心 MIB 的扩展，集成方提供可信总线适配。

## 控制和状态

| 地址 | 读 | 写 |
|---|---|---|
| `0x0000` | 当前模式：0 BYPASS、1 SHADOW、2 ENFORCE | 写影子模式；其他值拒绝 |
| `0x0004` | bit0 ready，bit1 pending，bit2 previous_valid | — |
| `0x0008` | 策略 epoch | — |
| `0x000c` | 当前 A/B 匹配窗口，周期 | 写影子值，不能为 0 |
| `0x0010` | — | `0x53454331` 请求提交完整影子表 |
| `0x0014` | — | `0x524f4c4c` 请求恢复上一规则版本；同时清空授权 |
| `0x0018/1c` | UTC 跳变上限 Q32.32 的低/高 32 位 | 写影子值，默认 2 秒 |
| `0x0020` | NTP 响应 RTT 上限，周期 | 写影子值，默认 12,500,000 |
| `0x0040/44` | RX would_allow / would_block | — |
| `0x0048/4c` | 输入完整帧丢弃数 / 审计事件丢失数 | — |
| `0x0050/54` | A/B 冲突数 / SHA-256 或签名长度不符数 | — |
| `0x0058/5c/60` | UTC 监测告警数 / 文件上下文超时数 / 观测帧数 | — |
| `0x0080 + 4*r` | 规则 r 的版本下限 | 直接单调提高，下调拒绝；复位后必须恢复 |
| `0x0100 + 64*r` | 当前规则 r 的 16 个字 | 写影子规则，r=0..15 |
| `0x1000 + 128*g` | 当前授权 g 的 32 个字 | 写影子授权，g=0..15 |

计数为 32 位自然回绕，复位清零。`would_allow/block` 表示检查结论，BYPASS/SHADOW 下不代表实际丢包。TX 为观察数据，不纳入 RX 准入计数；事件仍记录其检查结论。输入队列溢出的帧未进入引擎，不保证有逐帧事件，必须同时检查溢出计数。

## 规则表

| 字 | 含义 |
|---|---|
| 0 | bit0 enable；bits4:2 类型：0业务、1管理、2加载、3授时；bit5 允许有序业务分片；bit6 阶段约束标识；bit7 要求签名文件授权；bit9 冷启动也强制时间跳变上限 |
| 1 / 2 | 对端 IPv4 / 本地 IPv4，网络序整数 |
| 3 | 高16源 UDP 端口，低16目的端口；0 为通配。加载规则使用动态会话端口跟踪，不使用此静态端口匹配 |
| 4 / 5 | RX 目的 MAC 低32 / 高16，含 VL 标识 |
| 6 / 7 | RX 对端源 MAC 低32 / 高16；最后一字节 bit5/6 为物理接口差异，不参与身份比较 |
| 8 | 同一逻辑 RX 最小到达间隔，周期；正常 A/B 副本只扣一次 |
| 9 | 最大完整 MAC 帧长度，含 FCS、不含前导码，64..1518 |
| 10 | 本规则最大文件上下文数（含已完成文件的末块重传缓存）、最大分片上下文数，各自独立预算；0 拒绝新上下文 |
| 11 | 文件、分片与协议阶段空闲超时，周期，必须非零 |
| 12 / 13 | 速率窗口周期 / 每窗逻辑帧数；任一为 0 表示不启用窗口限制 |
| 14 / 15 | TX 观测目的 MAC 低32 / 高16；低32为0表示不限定。用于将本地请求关联回正确服务域 |

最先匹配的规则生效。用 `host/control.py:preflight()` 拒绝重复或重叠规则；它覆盖本插件的确切地址/端口规则类型，不是通用防火墙语言证明器。非首片按已有的规则/IP-ID 上下文关联，避免同一 IP/MAC 下不同 UDP 流共享错误的配额。

加载阶段固定为 0空闲、1初始化、2加载请求、3文件传输、4最终报告、5已完成。合法重传、协商 TID、最终报告 ACK 按该有界基线流程处理；未来扩展控制操作需明确扩展状态机。签名加载请同时设置类型2及 bit7。

## 授权表

| 字 | 含义 |
|---|---|
| 0 | bit0 valid，bits7:4 规则号，bits21:16 文件名长度 1..32 |
| 1 / 2 / 3 | 包版本 / 文件长度0..4096 / 从该策略提交周期开始的授权寿命 |
| 4..11 | SHA-256 摘要，8个网络序32位字，高字在前 |
| 12..19 | ASCII 文件名，字内小端，补零 |
| 20..27 | 256 位目标硬件 ID，低32位字在前 |
| 28..31 | nonce 前16字节审计标识；完整 nonce 由可信主机验证和持久去重 |

**写入授权表不是验签接口。** 只有可信主机运行真实 Ed25519 验签后可写；RTL 对实际收到的文件数据独立计算 SHA-256，在末块通过前不向原核心释放末块。先前数据仅进入原核心尚未发布的加载流程。文件数据与清单长度、摘要、目标、版本、租期均受检查；传输中改变硬件 ID、提高 floor 或授权过期会拒绝后续数据。授权完成的最终帧在准入时检查租期。

16个授权项是所有加载器共享容量。多加载器须用 `transaction()` 合并收据后一次提交；不能把两个分别清空未用槽的单加载器写序列直接叠加。回滚只恢复规则和模式，撤销全部授权，版本 floor 保持不降。

## 冻结的 A/B 原始证据

| 地址 | 含义 |
|---|---|
| `0x2000` | bit0 evidence_valid；写 `0x41434b31` 确认释放，需 cfg_ready |
| `0x2004` | 第一处差异的完整线上字节偏移；长度不同为 `0xffff` |
| `0x2008/0c` | 先到帧/后到帧长度 |
| `0x2010/14` | 先到帧到达周期低/高32 |
| `0x2018/1c` | 后到帧到达周期低/高32 |
| `0x2020` | 有冻结证据期间新冲突的证据丢失计数 |
| `0x2024` | 该冲突的策略 epoch |
| `0x2028` | bits5:2规则号、bits1:0后到帧通道 |
| `0x2100 .. 0x26ff` | 第一份完整原始线上帧，按32位小端读取 |
| `0x2900 .. 0x2eff` | 第二份完整原始线上帧，按32位小端读取 |

证据包括前导码与各自原始 FCS，冻结后跨策略提交保留，复位或明确 ACK 才释放。下一次冲突不会覆盖未导出的证据。位置比较排除前导码、FCS、源 MAC 的正常接口 bit5/6；其余 IPv4/UDP 校验字段本身可能先于业务字节出现差异，`host/evidence.py` 可列出全部差异。保存成功后调用方再 ACK。

## 160 位事件

| 位 | 字段 |
|---|---|
| 159:128 / 127:64 | epoch / 首字节到达周期 |
| 63:48 | flags，可同时置多项 |
| 47:44 / 43:42 | 规则号 / 通道：0 RX-A，1 RX-B，2 TX-A，3 TX-B |
| 41 / 40 | 检查允许 / 相同 A/B 副本 |
| 35:33 / 31:16 | 协议阶段 / 完整线上长度 |
| 15:8 / 1:0 | AFDX SN / 当前模式 |

flags：`0x001`格式、`0x002`地址规则、`0x004`双网内容、`0x008`协议阶段、`0x010`速率、`0x020`配额、`0x040`授权、`0x080`TID/重传内容、`0x100`时间响应、`0x200`孤儿分片、`0x400`SHA/文件长度、`0x800`分片覆盖/顺序。没有匹配规则时规则号为0占位，必须先看 ACL flag。事件 FIFO 默认32项；满时计数并丢事件，不反压原核心。

`sec_time_flags` 为最近一次 UTC 告警原因：bit0 单调时间倒退，bit1 UTC/单调时间增量不一致，bit2 锁定丢失。该监测有独立计数/粘滞总告警，不伪装成某一报文事件。
