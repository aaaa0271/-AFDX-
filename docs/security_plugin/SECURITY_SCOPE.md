# 可信边界与适用范围

## 实现及其证据

| 方向 | 实际实现 | 本包可以验证什么 |
|---|---|---|
| A/B 内容一致性 | 以 VL、对端身份、IPv4标识/分片、SN 等逻辑键关联完整帧；逐字节比较，排除源 MAC 正常接口位与各自 FCS；冻结原始证据 | CRC、IPv4/UDP校验均合法的内容冲突；接口位差异合法；冻结/ACK/证据满计数 |
| 阶段与会话 | 加载初始化、请求、文件、最终报告阶段；本地请求学习 TID；数据块顺序与精确重传内容检查 | 越阶段请求、错误TID、乱序、重复块改变内容被拒绝，合法重传与下一会话通过 |
| 资源预算 | 各规则帧长、最小间隔、窗口帧数、分片和文件上下文限额（含完成后的重传缓存）；全局有界队列与超时 | 规则间配额隔离、孤儿/覆盖分片、超时释放、事件满和输入队列满可观测且可恢复 |
| 策略更新 | 活动/影子/上一版本规则；离线冲突预检；空闲安全边界原子提交；epoch与撤销授权式回滚 | 会话中及 core_safe 为0时不出现半套规则；pending禁止写；非法配置拒绝；回滚不降低floor |
| 加载授权 | 可信主机真实 Ed25519 验签；目标/nonce/时效/版本校验及持久状态；RTL对实际文件字节计算SHA-256并扣住末块 | 内容替换、签名错误、nonce复用、回退、目标改变、传输中授权撤销；0/512/4096字节边界 |
| 时间可信度 | 每规则观测NTP请求，检查响应来源/原始时间/模式/版本/层级/RTT/跳变；选中服务UTC与单调时间交叉监测 | 偏移突变、异常延迟、未同步响应、重放、单调倒退、失锁告警与恢复 |

这些项目均有运行实现；“完整工业认证”“任意负载零损失”“所有标准版本全覆盖”不属于这里的验证结论。

## 必须信任的部分

- 可信本地主机、独立配置总线、设备ID来源、可信主机时间及预置验签公钥。网络来的“验签成功”字段或JSON收据不构成授权；收据只能在可信进程中直接生成和合并。
- `host/authorizer.py` 的 Ed25519 来自官方 cryptography 库。RTL实现的是实际 SHA-256，**没有在 FPGA 中实现 Ed25519，也没有用 CRC 冒充密码摘要**。若部署要求全硬件验签，应接可信处理器/安全芯片或另做验签核。
- 包内主机 JSON 状态带原子替换、进程锁、fsync 与 nonce去重，但它不是防物理回滚的可信 NVM。试验JSON读取限制为64KiB，nonce历史达到上限会拒绝继续授权，生产部署需在保持防重放语义的前提下实现有界日志与回收。系统集成必须把版本floor、nonce及必要发布状态放在受保护持久存储；复位后先恢复RTLfloor再安装授权。攻击者可回滚主机状态文件、替换公钥或控制总线时，软件文件本身不能提供硬件防回退保证。
- 版本下限在真实发布后由可信控制器提高。必须关联服务域、目标、清单与核心 `package_generation`/`service_loaded`；不能仅凭收到最终DATA或单个原始网络状态报文确认发布。跨断电的发布与floor持久化原子性需要目标平台实现恢复日志。
- 原核心的格式解析、非活动加载区与发布机制仍由原核心负责；插件先前通过的文件块可进入非活动区，末块校验失败时不应产生新发布。实际双加载器集成验证检查了最终已发布文件字节，不等同于所有可能故障的形式证明。

## 有界协议配置

默认16条规则、16个授权文件项、每通道4个完整帧槽、8个文件上下文及8个分片上下文、16条共享A/B历史、32个事件。文件授权上限4096字节，文件名1..32个ASCII字符；规则支持精确MAC/IP和通配UDP端口。各全局池共享，上限不是每个服务域都独占一份。需要更多并发域时应重新预算、增参、综合并验证。

接收检查为以太网/AFDX前导码、完整FCS、IPv4 IHL=5、UDP。非零UDP校验和会核对；零UDP校验和按本基线配置接受，不代表内容认证。拒绝不符合该有界配置的帧。业务分片仅支持按序、无重叠，最多8200字节IP负载；插件不重组UDP内容，完整业务重组及原标准策略仍由原核心执行。加载/管理/授时不接受IP分片。

加载规则跟随本基线LUI→LUR→文件RRQ/DATA→LUS/ACK流程，采用现有41000、42000..42999、40002等本地服务端口配置和512字节TFTP块，支持精确末块重传以及恰好512整倍数时的零长度终块。外部签名清单没有改变615A/665标准文件语法或线上控制文件。未来协议扩展、新控制操作、其他TFTP协商块长及更大文件需要增加明确配置与测试；本插件不是615A/665所有版本的替代实现。

MAC/IP白名单约束地址，不提供发送设备的密码学身份认证；攻击者伪造允许地址仍可能占用已允许的速率预算。签名清单保证被授权内容与目标/版本，不能证明每一帧究竟来自哪台物理设备。未使用网络层报文签名或NTP认证扩展。

## 双网与时间检测边界

A/B检测针对匹配窗口和有限历史内、具有相同逻辑键的两份副本。不同SN/不同逻辑消息、历史淘汰或窗口之外的报文不强行配对。重复SN/IPv4 ID的使用必须满足原系统的BAG/Skew窗口约束。先到帧可能已经交付；发现不一致只能拒绝后到冲突帧、告警并保留证据，**不能据此判断哪一网可信，也不能撤销已交付内容**。两网同时提供同样恶意内容不会被一致性比较识别。

NTP冷启动缺少已知UTC时，默认允许首个结构与会话合法的响应建立时间锚；后续受跳变上限限制。若启动已有可信时间，设置规则bit9，首次也强制上限。首个时间源自身的真实性仍取决于可信配置/认证时间源。UTC/单调监测在新锁定、策略切换、服务域选择变化时重新锚定，正常服务切换不自动当成攻击；异常原因保留为告警计数和flags。

## 性能与部署边界

ENFORCE为完整帧存储转发，必然增加延迟。SHA-256按有界文件逐轮计算，A/B逐字节比较也会占用共享检测引擎；恶意持续满速输入能超出默认处理预算。无RX反压接口时，队列满会丢弃后续完整帧并计数，绝不只向核心交付一段帧。BYPASS/SHADOW保持原时序，监测队列满仅损失检测覆盖，不改变原数据路径。

正常/异常混流的准入必须按实际VL BAG、帧长、授权文件大小、四通道叠加和SHA停顿重新计算；不能沿用未加插件时的容量证明。事件或证据满会丢失后续审计记录，必须消费并监控丢失计数；有限缓存不可能保存无限攻击流量。持续会话或流量可使安全策略提交等待，维护控制器要设置超时并执行可信停流，不应强行半套生效。

本包在Icarus执行RTL仿真，未执行目标器件布局布线、Fmax/SDC签核、BRAM映射验证、ModelSim/eLinx运行或板级MAC互通。宽向量帧历史、文件RAM访问和SHA实现都需要在目标器件综合后评估资源与关键路径。未宣称通过军工认证、适航认证或任何FIPS模块认证。
