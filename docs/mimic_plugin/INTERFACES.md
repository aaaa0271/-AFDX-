# 输入、执行器和集成接口

## 保护范围

本版保护固定IPv4头、完整未分片UDP帧的解析与静态白名单语义。输入必须包含8字节前导码/SFD、MAC帧、AFDX序号和FCS。合法线路总长72–1526字节；宿主输入上限2048字节，超出合法长度的受限输入由执行器一致拒绝。

校验顺序固定为：线路长度、前导码、FCS、EtherType、IPv4版本、IP边界、固定头支持范围、IP校验、分片范围、UDP协议、TTL、UDP长度、非零UDP校验、规则匹配、规则要求的非零校验和。IP选项与分片属于本插件首版不支持范围，明确拒绝；原网安插件原有状态功能并未删除或改写。

AFDX A/B报文分别作为独立输入接受异构复核，不把两张网当成拟态执行器。源MAC比对保留原接口标识归一化规则（屏蔽低字节0x60）；载荷不做这种归一化。跨网内容一致性和去重仍由原引擎处理。

## case.json

只允许schema=1、case_id、source、policy、frames。source取synthetic_lab、external_capture、hardware_capture，是采集方声明而非认证。case_id与帧id为最长64字符的字母数字、下划线、连字符。

policy是同目录内相对JSON路径。frames为最多256项列表，每项恰有id、path、channel、capture_ticks。channel为0或1，capture_ticks为非递减64位无符号整数；它供证据绑定使用，不是操作系统完成时间。

所有文件必须在case根目录内，拒绝绝对路径、上级路径、符号链接逃逸、重复JSON键、NaN/Infinity和未知字段。每输入文件上限1MiB，实际线路字节另限2048。运行开始固定全部输入哈希，结束复核；变化后撤销结论并拒绝导出为有效智能体证据。

## 策略JSON

恰有schema=1、epoch和rules。epoch为32位整数，rules为1–8项，按id排序后执行首条匹配规则。每项恰有：id、peer_ip、local_ip、rx_mac、peer_mac、source_port、destination_port、max_mac、require_udp_checksum。

id为0–15；IP为32位，MAC为48位，端口为16位；max_mac为64–1518字节，包含FCS、不含前导码；require_udp_checksum必须为布尔值。地址和端口使用整数，示例见cases/normal/policy.json。

本表是额外复核层自己的静态规则，不覆盖原引擎授权、签名、阶段、版本下限和资源预算。由可信配置方提供两层一致的规则。`update_policy`仅在没有在途帧时更新本地副本，并要求epoch逐次加一；它不更新设备寄存器，也不替代原可信配置事务。

## 执行器ABI

请求由宿主编码，采用网络字节序。固定96字节头：magic MDH1、64位请求号、32位epoch、32位调度代次、64位capture_ticks、8位channel、8位规则数、16位线路长度、32字节策略SHA256、32字节原帧SHA256。后随每条33字节规则和原始线路帧。规则编码详见contract.py中的RULE。

执行器读stdin，向stdout返回一个受限JSON。元数据恰有request_id、epoch、generation、policy_hash、input_hash；全部必须与本次请求相符。语义恰有verdict、reason、rule_id、wire_length、fields、payload_hex。

fields按顺序表示目的MAC、原始源MAC、源IP、目的IP、IP ID、AFDX序号、源端口、目的端口、UDP长度；payload_hex包含全部UDP业务字节。allow必须reason=OK、有效规则id且载荷长度吻合。deny使用确定原因、rule_id=-1、全零fields和空载荷，避免不同错误路径生成不可比的部分结构。

宿主最多读取8192字节结果，验证严格字段、类型、范围和绑定，再对完整语义对象计算SHA256用于裁决。调用同一身份多次不会变成多份投票。规范化原因不直接作为旧ML模型的输入。

## 调度与恢复

每实例只处理一个在途帧，固定三个在线执行器。默认请求截止时间500ms，受限配置范围20–5000ms；这是电脑进程的预算，不是AFDX实时保证。响应超过共同截止时间即排除；清理被终止进程可能产生额外宿主耗时。

默认每完成四个请求，在健康池中更换组合；存在替代集合时必须改变组合。正常运行使用系统随机源，demo使用明确记录的实验种子。少数分歧或进程/绑定错误触发隔离；隔离是保守处置，不代表已证实恶意。健康池不足三个时停止形成裁决，不降门槛。

执行器每次请求均从新进程执行，没有可迁移的加载/时间/分片会话状态。恢复首先核对原程序哈希，再运行全部黄金向量；成功后恢复资格。原程序已被修改时不会通过重写信任清单“自动修复”，需要可信管理员恢复发布文件并重新构建。

软件正常实例采用随机请求编号起点，实验实例可用固定编号以复现。硬件集成必须由可信宿主保证跨复位的请求身份不复用，并排空旧响应；单个实例内请求号和调度代次不允许回绕。

## 进程与程序信任

仅固定白名单执行器可启动，程序和编译器路径来自可信调用方，不读取case命令。子进程限制CPU、地址空间、文件大小、打开文件数和core dump；超时终止整个进程组。stdout/stderr先写受限临时文件，再按固定上限读取，防止无限输出占满宿主内存。

build.json记录源文件及可执行文件哈希；每次启动核对。该文件和宿主代码属于可信配置边界，不是数字签名。资源限制与分进程不等同于隔离不同用户、虚拟机或内核攻击的安全沙箱。

## 独立RTL裁决器

afdx_mimic_quorum_gate.v是单事务Verilog裁决器。start时固定request_id、policy_epoch、schedule_generation和三位有效的active_mask；四个独立结果通道分别携带身份、语义SHA256与allow位。只取每个活动成员第一次匹配结果。

至少两个语义摘要及allow位一致，并取得匹配的原引擎baseline结果，才形成最终门控。原引擎拒绝始终阻止放行；无裁决或缺少baseline到期拒绝。最终允许周期内到达的结果先参与裁决，再执行超时判断；done只发布一次。

宿主/桥接器必须确保摘要覆盖完整规范化语义，且身份与原帧一一对应；模块本身不计算SHA256或解析帧，也不认证总线发送者。它没有连接原MAC字节流、缓存、背压和重放器。DEADLINE_CYCLES是事务级参数，不代表异构解析已在该周期数内实现。原安全RTL和该裁决器目前分别仿真，不能据此宣称完整串联硬件已通过验证。

## 输出与命令行

report.md/JSON区分裁决、少数分歧、进程错误、调度/恢复和待验证事项。requests/保存每帧原始字节及所有执行器stdout/stderr、元数据和结果；selftests.json保存完整自检，build_info.json记录实际构建。trace.jsonl串联过程，integrity.json覆盖全部证据文件。

verify检查文件清单、逐文件SHA256、调用链及报告链尾；这些记录没有数字签名，不能防止具备写权限者重新计算全部哈希。CLI正常结束返回0，输入/工具启动错误返回2，无裁决返回3，输入完整性失败返回4。common_mode正常演示完成可返回0，但明确标记为局限，绝不表示错误多数已被识别拦截。
