# 威胁假设、来源与实现边界

本插件采用动态异构冗余的输入复制、独立执行、结果裁决和反馈调度结构。设计参考：

- IEICE，A Self-Adaptive Mimic Scheduling Method Based on Fine-Grained Heterogeneity，DOI 10.1587/transfun.2024EAP1082。https://globals.ieice.org/en_transactions/fundamentals/10.1587/transfun.2024EAP1082/_f
- NIST SP 800-160 Vol.2 Rev.1，关于Diversity、Redundancy和Dynamic Positioning的系统工程考虑。https://csrc.nist.gov/pubs/sp/800/160/v2/r1/final

上述资料支持机制和共模风险背景，不为本插件提供认证或性能保证。本项目的隔离阈值、协议子集和接口是本次具体工程选择。

## 可以验证的性质

当三个在线执行器中至少两个遵循同一规范、使用正确一致的策略，并在预算内完成，且宿主分发/绑定/裁决可信时，单个执行器给出不同语义或缺席不会改变正确多数结果。测试包括语义伪造、崩溃、超时、旧epoch、旧调度代次、错原帧摘要与重复身份。

这是一条带假设的性质，不意味着能发现所有漏洞。若两个健康执行器本身对规范解释有同一错误，多数仍可能错误；若攻击者控制宿主、裁决器、策略或结果通道身份，也超出假设。

## 实际异构程度

四份解析器独立编写，没有共享解析函数或策略判定函数。结构分别为Python struct、C固定偏移、C++检查游标及Python声明式memoryview。CRC采用标准库、逐位算法或半字节查表；互联网校验和采用不同组织方式。协议ABI和预期语义必须共享，否则无法比较。

Python备用实现共享解释器，C/C++共享本次GCC编译器系列，所有进程共享操作系统和硬件。不同语言并不自动保证漏洞独立，代码独立也不排除共同规范错误。当前未实现不同内核、不同CPU或不同FPGA架构的硬件异构。

## 故障注入与恢复

lab_proxy.py是显式实验装置：先实际运行被选执行器，再替换结果，或模拟超时、崩溃。它不是真实漏洞利用，不证明某种攻击能攻破生产执行器。普通run案例禁止携带此类指令，只有可信调用方选择固定demo可以启用。

所有执行器采用一次性进程，恢复体现为从未变的可信程序重新启动并通过完整自检。没有容器镜像清洗、操作系统重装、FPGA动态部分重配置或密钥轮换。重启有漏洞的同一程序不会消除漏洞；黄金自检也不证明不存在未覆盖的恶意行为。

## 可用性与实时约束

攻击可以诱发分歧、超时或池耗尽，导致保守拒绝，必须单独评估误拒绝和业务可用性。shadow仅观测；enforce的无裁决拒绝策略需要业务安全负责人在系统集成时确认。

Python/C/C++电脑进程的完成时间不构成AFDX线速或最坏时序证明。未来串联到MAC路径必须设计队列、截止时间、背压及溢出策略，并完成多端口满负载、抖动、延迟、资源和板级验证。AI时延预测不替代这些证明。

## 保留的既有安全边界

原签名授权、硬件白名单、加载阶段、版本下限、A/B内容检查和可信配置流程继续由原网安插件负责。拟态层无权通过多数票放宽这些检查，也不随机修改MAC、VL、BAG或标准文件语法。

旧智能体只读访问本插件证据。没有完整真实观测窗口时不补齐ML特征，不据模型结果直接修改在线策略或切换物理设备。软件调度器只管理本插件进程；原AFDX会话状态不复制、不迁移。
