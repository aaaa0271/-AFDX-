# 安全、AI 与拟态统一集成

## 正式入口

`AFDX_defense_top` 是当前 `ARINC.epr` / `ARINC.qsf` 的统一顶层。它真实实例化原 AFDX 端系统、安全引擎、完整帧拟态桥、原 `afdx_mimic_quorum_gate` 和原 `afdx_ai_tcn_plugin`。不是将三个独立测试的 PASS 拼接为集成结论。

```text
原始 A/B MAC 输入
    -> 安全插件：FCS/协议/规则/阶段/TID/配额/授权
    -> 有界完整帧队列
    -> 可信宿主四个独立执行器中的三票及轮换
    -> RTL request/epoch/generation/完整语义 SHA-256 裁决
    -> 原安全允许 AND 语义多数允许 AND 未处于 AI 限时阻断
    -> 整帧重放 -> 原 AFDX 接收、重组、SNMP、加载和 RTC

真实原始计数/帧证据 + 协议状态
    -> 原子测量快照 -> 宿主 log1p/标准化/INT16 预处理
    -> 八窗口 TCN RTL -> CSR 结果和告警 -> 可选限时接收阻断
    -> 原有 AI 智能体读取同一测量窗口及实际报文、推理与裁决证据
```

外发业务与服务仍走原 A/B 发送路径；安全插件观察 TX 学习加载与 NTP 会话，不能截断正在发送的帧。新增拟态/AI 阻断作用在 RX 的完整帧放行边界。安全拒绝不能由多数允许或 AI 输出覆盖。

## 宿主协同的实际含义

拟态原插件是 Python/C/C++ 的四执行器设计，不是四套 FPGA AFDX 硬核。本版将它们**接到实际准入路径**，没有把同一解析函数调用三次冒充异构。两套 Python 执行器仍共享解释器，是明确的共同失效风险。新增 `host/defense_runtime.py` 接受可信本地 `read32` / `write32` 完成回调，提交实际捕获帧，读取各进程结果，写入 RTL 裁决表并同步隔离/轮换后的 active set。

没有宿主、没有三个合格执行器、无一致语义、过期请求、队列满或超时均拒绝整帧。它不是脱离宿主的 FPGA-only 拟态方案。传输回调必须自行实现物理访问超时，不能来自普通网络报文。

Windows 支持显式 `.exe`、二进制 stdin/stdout、静态链接运行库，以及每工作进程所属的 Windows Job 资源/进程树限制。POSIX 继续使用原 `resource` 与进程组。限制不等于抵抗同用户/内核攻击的安全沙箱。验证脚本会实际编译和启动四执行器；缺少 GCC/G++ 硬失败，不回退成伪造响应。

## 端口与寄存器

统一顶层保留可配置端系统和 `sec_*` 接口，新增 `defense_cfg_valid/write/addr/wdata/ready/error/rdata` 可信本地总线，所有访问按 rising-edge ready/valid 完成。地址不与旧安全寄存器混用。

| 地址 | 用途 |
|---|---|
| `0x0000..0x0054` | 原 AI CSR：身份、model tag、作业、144 个特征、结果及 ACK |
| `0x0100` 写1 | 原子捕获真实测量快照 |
| `0x0100..0x01fc` 读 | 64 个快照 word：时钟、epoch、原始帧/字节/方差/间隔/FCS、队列、安全、拟态、RTC、加载和上下文数据 |
| `0x0200` | 可信控制器显式使能 AI 自动处置；复位默认关闭，但真实 AI 推理和告警不关闭 |
| `0x0204` | 允许触发处置的候选位掩码 |
| `0x0208..0x021c` | 告警/阻断状态、剩余时限、推理/处置次数、最近结果 |
| `0x1000..0x1034` | 拟态身份、状态、request id、epoch、generation、active mask、帧长、原始捕获时间 |
| `0x1040` | 写入已准备好的独立执行器响应有效位 |
| `0x1044` | 完成本帧；提交下一帧 active set/generation。变更 active set 必须递增 generation |
| `0x1048 / 0x104c` | 下一帧 active mask 与 generation；不能在当前裁决中途改成员 |
| `0x1050..0x1074` | 放行/拒绝/超时/溢出/AI 拒绝/过期响应计数、最近请求及实际准入延迟 |
| `0x1100..0x11fc` | 四个执行器槽，每槽64字节：id低/高、epoch、generation、allow、8个SHA-256 word；低word先写 |
| `0x1800..0x1dfc` | 当前不可变完整帧，低字节优先读取；不是只摘要、不传真实报文 |

所有响应由宿主校验 input hash、policy hash、请求绑定和完整规范化语义后提交。RTL 再检查请求号、策略版本、调度代次、活动成员与语义 SHA-256。此处信任本地宿主，不声称能抵抗已经控制可信总线的攻击者。

## 不破坏既有协议

拟态默认仍拒绝分片；仅显式 `allow_fragments=true` 的规则启用扩展语义。四个解析器分别检查分片结构和地址，比较含完整 IP header、分片标记和片段字节的语义摘要；原安全引擎和 AFDX 核继续负责上下文、顺序、配额、校验与最终重组。不是忽略分片错误。

615A 控制/数据/报告 TID 是动态的。`multiplexed_rules` 必须由可信集成者显式列出；宿主只对这些规则投影实际端口，原安全插件依然先检查会话阶段、TID、签名授权和配额，不能用宿主端口投影绕过原引擎拒绝。

拟态保留原始捕获 cycle stamp，叠加安全和拟态两层缓存延迟后再交给 RTC；T1 仍观察最终外部 TX。NTP 不能把宿主等待时间误认为网络对称往返时延。

## AI 测量与处置

18 个输入字段沿用冻结模型的量纲与预处理。`collect_window()` 从实际快照与对应帧记录计算；NTP 尚未成功、窗口为空或缺少实测延迟时，明确返回缺测，不用常量零补齐。连续8个完整窗口才会启动 TCN。

输入越界、模型不匹配、缺特征、计算饱和等状态保留诊断证据，但不能触发自动处置。有效候选也只是候选，不代表确认物理根因。显式使能后，AI 只能在 `AI_BLOCK_CYCLES` 的有限时限内追加 RX 阻断，不能放宽规则、改加载授权或撤销原安全拒绝；时限结束自动恢复。已开始重放的帧不被中途截断。

原 AI 智能体通过 `DefenseRuntime.investigate()` 消费同一实际窗口、实际报文和硬件推理/拟态结果，生成可审计诊断报告；智能体建议不直接改策略。

## 验证与时序边界

```powershell
# 全量 ModelSim、宿主真实异构进程和统一链路，不运行 eLinx 展开。
python -B -u scripts/run_all.py --hdl-only --workers 8

# 只运行统一链路及硬件准入边界。
python -B -u scripts/run_all.py --hdl-only --tests tb_defense_live tb_defense_boundary
```

集成用例实际驱动 NTP、615A/665 加载、业务报文、IP 分片、执行器分歧、宿主缺失、AI 推理及限时阻断，并检查真实应用交付。正向 AI 处置使用明确标为合成验证向量的模型输入，不能把它描述为真实攻击检测；真实窗口推理另行比对整数参考结果。中间失败日志保留，不当作最终通过证据。

ModelSim 与宿主使用可信回调协同仿真，宿主计算期间仿真时钟暂停。**这验证数据流、状态、拒绝语义和有界 RTL 截止行为，不证明 Windows 宿主可在100Mbps线速下逐帧裁决。** 真正实时部署必须为平台选择合适的硬件截止预算、宿主处理能力和缓冲容量；预算不足的行为是超时丢帧，不是放行。用户本轮明确排除上板，并暂不执行单域/双域 eLinx 展开，故不提供这些新增证明。
