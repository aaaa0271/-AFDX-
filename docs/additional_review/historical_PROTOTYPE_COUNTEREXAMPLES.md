# Sub-VL/SAP 原型独立反例审计

日期：2026-10-10。本审计不修改生产 RTL，也不修改冻结中的回归输入。执行证据位于 `results/prototype_audit_20261010/`。

ModelSim 确认以下四个反例（审计脚本本身 probe_errors=0，表示反例复现成功，**不是被审原型通过要求**）：

1. 连续写入采样值 16、64 后，原型输出仍为 16，没有正确选取最新待发采样。
2. 两个 Sub-VL 归于同一 VL，配置 BAG=20 个周期，原型可相邻 1 个周期就再次提供发送，没有统一 VL 级 BAG。
3. 队列同时出队/入队后，第二个消息丢失；非阻塞赋值覆盖使计数减为 0。
4. 原型输出被背压时，新端口入队会把有效输出从 port0 改为 port1，缺少事务保持。

受测对象：`tb/afdx_sap_subvl_model.v`，不是已集成顶层 `rtl/AFDX_competition_top.v`。现有端口生产回归通过不能消除这些新功能原型的反例。

### 处理

- 原型留在实验区，不参与生产顶层 eLinx 设计文件集。
- 第 1 项完整 Sub-VL/SAP/多端口要求继续 OPEN。
- 原型既有 smoke 用例即使 PASS 也不能解释为完整需求 PASS。
- 后续修复应先确定采样更新、发送事务锁定、每 VL BAG、入出队同周期和多消费者的明确语义，再增加能覆盖这些反例的统一顶层验证。
