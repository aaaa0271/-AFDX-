# 演示与正式验收入口

2026-10-20 起正式集成入口为 `AFDX_defense_top`，包含安全、AI 和拟态，详见 `DEFENSE_INTEGRATION.md`。本文八端口 `AFDX_top` 继续是基础端系统自主演示，不能通过八个 MAC/时钟引脚驱动额外的可信宿主总线；八端口安全版固定 BYPASS，仅作兼容对照。题目接口为设计建议，不冒称强制评测入口。

## 八端口行为

- `clk` 默认 12.5 MHz，`reset` 高有效。
- `rx_data/rx_valid` 是包含 preamble/SFD/FCS 的输入帧，不是应用字节。相同输入同时送入 A/B；`tx_data/tx_valid` 输出 A 网完整 MAC 字节流。两个独立物理网络的验收应使用可配置顶层。
- `tx_ready` 表示复位结束且配置已封存且无配置错误，不是逐字节握手。`rx_ready` 是网络发送准入条件，在帧边界采样，不能用它在帧中途截断 GMII 帧。
- 复位后写入四个 RX VL 及四个 TX BAG 配置，在无写入周期封存。配置失败时不报告 ready。
- 默认每 1,250,000 周期发送一条 16 字节业务状态消息，轮换 VL0..3；默认每 12,500,000 周期发起 RTC 轮询，忙碌请求不重入。应用字节只在 `app_wr_accept` 时推进，背压保持数据和 SOF/EOF。
- `hardware_length=3`，低字节优先的 `hardware_id=24'h4d4953` 对应 ASCII `SIM`，与交付 LUH 向量一致。
- 默认加载端 `10.0.0.1`、时钟端 `10.0.1.1`，服务本地 IP `10.0.0.16`。加载和镜像读取确实连接到内部服务，而非虚设有效位。

## 业务预置

对于 `i=0..3`，目的组播 MAC 为 `03:00:00:00:00:(40+i)`，源 IP `10.0.0.(32+i)`，目的 IP `10.0.0.16`，UDP 源端口 `10000+i`、目的端口 `20000+i`，BAG 为 `CLK_HZ/1000`（默认 1 ms），LMAX=1518，Sub-VL0、分区0。相同配置可接收对应的业务回环帧。服务地址不与业务 VL 混淆。

## 状态报文

所有多字节状态整数为低字节优先；其外层 Ethernet/IP/UDP 仍按网络字节序。

| payload 字节 | 内容 |
|---|---|
| 0..3 | ASCII `AFDX` |
| 4..7 | 应用消息序号 |
| 8..11 | 已交付业务接收字节数 |
| 12 | bit0 RTC locked，bit1 image valid，bit2 loading，bit3 load failed |
| 13 | 最近收到的业务字节 |
| 14 | 当前已提交镜像的一个字节；每生成一条消息后读取地址递增，到文件末尾回绕 |
| 15 | 当前镜像长度低 8 位，仅作演示提示，完整 16 位长度从正式配置接口读取 |

每条消息在开始时冻结快照，背压期间不改变其内容。镜像读取默认为文件0。完整文件选择、元数据和任意地址读取使用正式可配置入口。

## 参数与验收

`CLK_HZ`、`DEMO_INTERVAL_CYCLES`、`RTC_POLL_CYCLES`、`SERVICE_TIMEOUT_CYCLES`、`LOADER_IP`、`TIME_SERVER_IP` 可在综合/仿真实例化时设置，不增加八端口接口。时钟频率必须支持非零合法 BAG。

`tb_review_8port` 和参数化的 `tb_review_security_8port` 从这两个真实封装驱动 LUI/LUR/LUS、LUH、700/1024 字节文件加载、RTC、业务发送与 16 字节接收回环，检查已提交镜像与状态报文；`verify_demo_wire.py` 独立校验 FCS、IP 校验、长度、序号、文件请求及最终报告。测试中的单台模拟加载/时钟服务器通过 `TIME_SERVER_IP=10.0.0.1` 显式选定。

`tb_review_rtc_mac` 则使用默认分离的时钟地址、独立参考时钟和自己构造的 Ethernet 回包，在发送等待 0/200/400 周期、业务竞争、两个无效回包占用接收队列时检查实际 MAC 时间戳与锁定精度。它不以 DUT 的当前时间生成校时 oracle。
