# 器件与系统接入

## 保持插件边界

本插件不修改既有 AFDX、网安、拟态或智能体源码。原项目的 `ARINC.epr` 声明器件为 eHiChip6 / EQ6HL130；`ARINC.qsf` 自带说明，其 Stratix 型号为兼容检查占位值，不能作为真实目标器件。

接入时在系统外层包装中实例化 `afdx_ai_tcn_plugin` 或 `afdx_ai_csr`，将其接到独立可信本地数据通道。AI 输出作为带模型版本的诊断证据，由现有可信配置流程决定是否应用建议。主业务链没有新增 AI 反压依赖，也没有 AI 自动改时钟、加载内容或防火墙配置的连线。

当前未提供基于猜测引脚的板卡顶层。目标工程需指定真实总线桥、复位同步、时钟来源、引脚和 I/O 时序。`integration/files.f` 列出 RTL 文件；`integration/ai_clock_example.sdc` 仅给出仿真采用的时钟示例，不能代替全工程约束。

## 数值实现

发布模型使用按输出通道的二进制权重尺度，移位常数从 ROM 读取。激活分别有 10、9、8 个小数位，最终输出有 8 个小数位。乘积为 signed 32 位，累加为 signed 48 位，舍入为最近值、半值远离零；每层显式进行范围检查。

卷积权重在 `weights.mem` 中按输出通道排列，第一层 864 项，第二层 768 项，最后全连接 288 项；偏置共 41 项，阈值 8 项，移位 41 项。ROM 通过 `$readmemh` 初始化。器件工具必须支持此初始化形式，或者在可信构建阶段按工具要求转为 ROM/IP 初始化文件；转换后重新做仿真和比对。

代码采用通用寄存器/数组写法，包含异步读取。是否映射到块 RAM、分布式 RAM 或寄存器，由目标工具决定。通过 Verilog 语法检查不能推断 BRAM、DSP、LUT 数量，也不能推断 EQ6HL130 的最大时钟。

模型在构建时固定，没有在线写权重接口。更新模型需重新导出全部 ROM 和 `ai_model_params.vh`，重新构建并通过既有可信发布流程部署。32 位 model_tag 用于发现误配；完整 SHA-256 在主机发布清单中核对，它们均不替代签名认证。

## 特征采集

第一阶段由主机提供完整原始 8×18 窗口，并在发送作业前完成 `log1p`、标准化、有效性检查与量化；FPGA 完成神经网络本体推理。最后的 sigmoid 和时延物理单位恢复也在主机完成。

原计数器桥只提供部分输入能力，可估计 observed_pps、queue_overflow_ratio；帧大小分布、到达离散度、双网内容差异、时延分位数、时间响应、加载状态和重组上下文等仍需要独立测量生产者。不能把缺失字段置零后宣称实现了全硬件在线检测。

要扩展为完整 FPGA 特征链，先固定统计窗口与测量点，再为每项增加旁路采集、有效掩码、原子快照及跨域桥接；若实际可用特征与当前模型不同，应重新训练对应模型。该扩展未纳入本版完成项。

## 主机驱动

独立 CSR 驱动在 `afdx_ai_hw/csr.py`。向它传入真实总线的 `read32(addr)`、`write32(addr,value)` 回调即可；回调必须处理 cfg_ready、cfg_error、端序和传输超时。该类不会自行连接串口、网口或扫描设备。

输出结果在 ACK 前保持不变。驱动会核对魔数、模型标识、job_id、候选掩码、保留位和正常结果周期数。发现绑定不一致时保留结果并报错，供上层调查；不会悄悄消费异常结果。

输入超时按连续空闲周期计数，默认 65536 周期。慢速传输应增大参数或在本地缓冲好整个窗口后再发作业。主机、FPGA 流接口和 CSR 包装均只允许单个在途作业。

## 尚需目标环境完成

- 使用真实 EQ6HL130 工具对最终系统包装综合、布局布线，检查所有时钟、I/O、跨域路径和资源余量。
- 在真实观测来源上核对特征语义，记录窗口时长、时间戳、采样误差、复位和配置 epoch。
- 板上逐位核对固定测试向量，再测从特征就绪到主机接收结果的完整延迟。
- 使用实际业务、异常和最坏背景负载检查主业务延迟、AI 数据丢弃策略、温度、功耗与运行稳定性。

这些事项不在本包中计为 PASS。仿真时钟周期仅是测试台激励，实际器件能否达到该频率需要时序报告证明。
